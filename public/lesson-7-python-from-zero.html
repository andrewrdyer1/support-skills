Python from zero

Lessons 7 to 10 start from nothing: where Python runs, how to run it, and the language one piece at a time, with a small exercise after each piece. By the end of Lesson 10 you'll have written and run a real script.

How these lessons work

Grey Run boxes are real Python on your Mac: change anything and run it again. Exercises check your code with hidden tests and tell you which case failed. A few steps happen in your own Terminal, because that's where you'll run scripts at work. Your code is saved in this browser as you type.

If you use Cursor, turn off its Tab autocomplete while you practice (Cursor Settings → Tab). It will happily write the answer for you, and then you won't have learned it.

1. What Python is for in this job

Support engineers and CX operations people don't build apps in Python. They write small programs, usually 30 to 150 lines, that do a boring job faster and more reliably than a person would. They run in a few places:

WhereWhat it looks like
A script on your laptopA .py file you run from the terminal: pull data from an API, clean a CSV, update a batch of tickets. The most common by far.
A notebook (Jupyter, Google Colab, Hex)Code in cells with the results shown under each one. Used for one-off digging and charts, especially in CX ops. Lesson 10 has one.
A scheduled job (cron, GitHub Actions)The same kind of script, run by a server every hour or every morning: an SLA alert, a nightly report.
Inside another tool (Zapier, Retool, Workato)A short snippet that reshapes data between two systems.
The product's own codeFollowing a stack trace into engineering's code, if the product is written in Python.

The everyday toolkit is an editor (Cursor or VS Code), the terminal, a virtual environment with the libraries the script needs, and git to share it. Every one of those appears in these lessons.

3. The course's Python

Type these two lines in the terminal:

cd ~/Developer/support-skills
source .venv/bin/activate

Your prompt now starts with (.venv). You've switched on a virtual environment: a private copy of Python inside this project, with its own libraries (requests, pytest and a few others). Every Python project at work has one, so that one project's libraries can't break another's.

Now check which Python you're running:

python --version
Do this in every new terminal window

Activating only lasts for that window. If you ever see command not found: python, or ModuleNotFoundError: No module named 'requests', you're in a window where the environment isn't on. Run the two lines again. (On a Mac, Python outside an environment is called python3, which is why plain python isn't found.)

4. Two ways to run Python

The interactive prompt. Type python and press Enter. The prompt changes to >>>, and each line runs as soon as you press Enter. Try 2 + 3, then "paperkite".upper(). It's for trying one small thing. Type exit() to leave.

A file. Real scripts live in .py files that you run with python plus the file's path. The course's files live in workspace/, and you always run them from there:

cd workspace
python lesson7/first_script.py

Open workspace/lesson7/first_script.py in your editor and look at how the three printed lines come from the code. Then change it to ticket #1151 from Lesson 1: id 1151, subject Our new bookkeeper never got his invite. Save, press ↑ in the terminal, and run it again.

That's the whole loop of scripting: edit, save, run, read the output. The Run boxes on this page do the same thing for you in one click.

5. print and comments

print(…) shows something. Separate several things with commas and they're printed with spaces between. A # starts a comment: Python ignores the rest of the line. Comments are for whoever reads the script next, often you in three months.

7. Variables

A variable is a name for a value. = means "store this value under this name" (not "equals": that's ==, in Lesson 8). Use it later by name:

Python names are lowercase with underscores between words (open_tickets, not openTickets), can't start with a number, and are case-sensitive: Customer is a different variable from customer. Pick names that say what the value is. amount_cents beats x every time.

Notice /. In Lesson 2, Postgres's 7 / 2 gave 3. In Python it gives 3.5. Same symbol, different rules, which is why you check results instead of assuming.

Two things worth knowing. :,.2f inside the brackets of an f-string means "commas between thousands, exactly 2 decimals". And decimals like 0.1 can't be stored exactly, so tiny errors creep in. That's why payment systems, Paperkite included, store money as whole cents, and only turn it into dollars to show it.

9. Text

Strings come with methods: built-in actions you call with a dot. They return a new string and leave the original alone.

WriteGives you
s.strip()without spaces (and line breaks) at either end
s.lower(), s.upper(), s.title()lowercase, UPPERCASE, Title Case
s.replace("a", "b")every "a" swapped for "b"
s.split("@")a list of the pieces between each @
s.startswith("INV"), s.endswith(".co")True or False
"pine" in sTrue if that text appears anywhere in s (case matters)
len(s)how many characters

You can also pick characters out by position. Positions start at 0, not 1. s[0] is the first character, s[-1] the last. A slice, s[start:end], gives the characters from start up to but not including end; leave either side out to go to the edge.

You'll practice slicing at the end of the next section, once you can turn "0046" into a number.

10. Converting between types

Data that comes from outside your script (a CSV, a form, a command-line argument) arrives as text, even when it's a number. Convert it before doing math:

WriteGives youFails on
int("42")42int("4.5"), int("abc"): ValueError
float("12.50")12.5float("$12"): ValueError
str(42)"42"never fails

Read the error at the bottom: TypeError: can only concatenate str (not "int") to str. Errors aren't a sign you've done something wrong; they're Python telling you exactly what it couldn't do. The last line is the one to read first. Lesson 9 is about reading the rest.

Formatting a number as you print it

Converting a number back to text is where its format can go wrong. int("0046") is just 46, so the leading zeros are gone, and f"INV-{47}" prints INV-47, not INV-0047. To fix that, put a colon after the value inside the f-string's curly brackets, followed by a format code. The code changes how the value looks, not the value itself.

WriteMeansPrints
f"{47:04d}"d: a whole number. 04: at least 4 wide, padded with zeros0047
f"{1234.5:,.2f}"f: a decimal. .2: 2 places. ,: commas between thousands1,234.50
f"{0.237:.0%}"a percentage, no decimals24%

The colon divides the curly brackets into two parts: on the left is the value, which can be any expression (number + 1 is fine), and on the right is how to show it. So read {number + 1:04d} as "work out number + 1, then show it as 4 digits with leading zeros". The 1 belongs to the math, not to the format.

Recap

  • Activate the environment in every new terminal: source .venv/bin/activate. Run scripts from workspace/ with python path/to/file.py.
  • python on its own opens the >>> prompt for trying one thing; exit() leaves.
  • Types: str, int, float, bool (True/False), and None. type(x) tells you which.
  • = stores a value under a name. Names are lower_with_underscores.
  • f-strings: f"#{ticket_id}: {subject}"; money as f"${amount:,.2f}", zero-padded as f"{n:04d}".
  • / always gives a float. Store money in cents.
  • String methods: .strip() .lower() .split() .replace() .endswith(); positions start at 0; slices stop just before the end.
  • Outside data is text: int(), float() and str() convert.
