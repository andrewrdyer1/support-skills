Your prompt now starts with (.venv). Type python for an interactive prompt where each line runs as you press Enter (exit() to leave), or python some_script.py to run a file. That .venv folder is a virtual environment: a private copy of Python with its own packages, so this project's libraries don't mix with anything else on your machine. 3. Lists and dicts

A list holds values in order. Positions start at 0, and negative positions count from the end. A dict holds values by name, exactly like a JSON object. Most data you'll handle in Python is a list of dicts, which is what an API's JSON or a CSV file becomes.

4. if, loops, and comprehensions

Conditions use if / elif / else, a colon, and an indented block. and, or, not are words.

Truthiness is different from JavaScript

In Python, an empty list [] and empty dict {} are falsy, as are 0, "" and None. So if tickets: means "if there are any tickets." (In JavaScript, an empty array is truthy.)

A list comprehension builds a new list from an old one in one line. Read it like SQL: select this, from that, where something.

key=lambda t: t["id"] tells sorted what to sort by: for each ticket t, use t["id"]. A lambda is a tiny unnamed function, like an arrow function in JavaScript.

5. Functions

def, a name, parameters, a colon, an indented body, and return. A function without a return gives back None. Parameters can have defaults. The string right under the def line is a docstring, which describes what the function does.

6. Errors, tracebacks and try/except

When Python hits an error it prints a traceback. It's the same idea as the JavaScript stack trace in Lesson 6, but upside down: Python says "most recent call last", so read it from the bottom. The last line is the error; the line above it is where.

The bottom line, AttributeError: 'NoneType' object has no attribute 'split', is Python's version of "Cannot read properties of null." The errors you'll see most:

ErrorUsually means
SyntaxError, IndentationErrorA missing colon, bracket or quote, or indentation that doesn't line up
NameErrorA misspelled variable, or using it before it's defined
KeyError: 'x'A dict has no key 'x'; use .get() if it might be missing
TypeErrorWrong kind of value, like "5" + 1
AttributeError: 'NoneType'…Something you expected to have a value is None
ValueErrorRight type, bad value, like int("12.50")

Recap

  • None is null; test it with is None. True/False are capitalized.
  • f-strings: f"#{id} {subject}". Strings have .strip() .lower() .split(), and in.
  • Lists [] are ordered; dicts {} are JSON objects. Use d.get("k") when a key might be missing.
  • Indentation is syntax. if/elif/else, for x in items:, def f(x): all end in a colon.
  • Comprehensions: [x["id"] for x in items if x["status"] == "open"].
  • Read tracebacks from the bottom. Catch the specific errors you expect.
