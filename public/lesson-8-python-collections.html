Lists, dicts and loops

Lesson 7 handled one value at a time. Support work is never one ticket: it's the queue, the export, the API response with 200 invoices in it. This lesson is about holding many things and doing something to each of them.

Indentation is part of the language

From here on, code has lines that end in : followed by an indented block. The indent (4 spaces) is how Python knows which lines belong to the for or the if. Get it wrong and the code means something else, or doesn't run at all. In these editors, Tab indents by 4 spaces and Enter after a : indents the next line for you.

1. Lists

A list is an ordered collection, written in square brackets. Like strings, positions start at 0, -1 is the last item, and slices work the same way.

Lists of numbers have a few built-in helpers: sum(amounts), min(amounts), max(amounts), and sorted(amounts), which gives back a new list in order.

2. for loops

A for loop runs its indented block once for each item, with a name you choose holding the current item:

The most common loop keeps a running result: start empty or at zero before the loop, update it inside, use it after.

To repeat something a set number of times, loop over range(n), which counts from 0 up to n - 1: for attempt in range(3): runs three times.

3. Making decisions

if runs its block only when the condition is true. elif ("else if") tries another condition, and else catches everything left. Only the first matching branch runs.

Truthiness

You'll see if tickets: with no comparison. Python treats some values as false on their own: None, 0, "" (empty text), and [] (an empty list). Everything else counts as true. So if tickets: means "if there are any tickets." It's handy, and it's a trap: a price of 0 or an empty name also counts as false. When you mean "has no value", write is None.

4. Dicts

A dict (dictionary) stores values under keys, in curly brackets. If you've seen JSON, you've seen dicts: it's the same shape.

Use ticket["status"] when the key is always there and a missing one is a real problem you'd want to hear about. Use ticket.get("status") when it might not be there. Data from outside your script is the second kind more often than you'd hope.

None is Python's version of SQL's NULL and JSON's null: "no value". You test for it with is None and is not None, just as SQL uses is null. Square brackets never give you None for a missing key, so this crashes before the check runs:

Quotes or no quotes

ticket["client"] with quotes means the key spelled c-l-i-e-n-t. totals[client] with no quotes means "whatever is in my variable client right now", which might be "Lakeshore Group" on one pass of a loop and "Greenway Farms" on the next. Quotes are the literal word; no quotes is a variable's value.

A first look at functions

The next few exercises ask you to fill in a small function. Lesson 9 covers them properly; here's just enough to read one.

def describe(plan):          # def, the function's name, its input in brackets, a colon
    price = PRICES.get(plan) # the indented body: runs only when the function is called
    return f"{plan}: ..."    # return hands the answer back to whoever called it
  • def doesn't run anything. It writes the recipe down. Nothing inside happens until a line calls it, like describe("pro").
  • The name in brackets is a placeholder. In describe("pro"), plan is "pro" for that one call; in describe("gold"), it's "gold".
  • return, not print. return gives the answer back to the caller, which can store it or print it. print only shows it on screen, and the caller gets None.
  • The Check button calls your function with its own data. It tests whether your function works for any input, not just the example at the bottom. If you put a print inside, you'll see the checker's values appear, not yours.

6. Counting and adding up by group

The single most useful pattern in support scripts is SQL's group by, done with a dict: one key per group, and add to it as you loop.

Recap

  • Lists: [a, b]; x[0], x[-1], len(x), .append(), in, sum/min/max/sorted.
  • for item in items: plus an indented block. Keep a running total that starts before the loop.
  • if / elif / else; == compares, = stores; is None for "no value". Empty things and 0 count as false.
  • Dicts: d["key"] when it must be there, d.get("key", default) when it might not be.
  • API data is dicts and lists inside each other: go in one level at a time.
  • Group with a dict: counts[k] = counts.get(k, 0) + 1.
