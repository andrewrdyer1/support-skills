Files and your first script

Support data arrives as files: a customer's CSV export, a JSON log, an API response saved to disk. This lesson is about getting that data into Python, one piece at a time, then putting your functions together into a script you run from the terminal. It ends with the same data in a notebook.

1. import: using code that isn't yours

Python starts with only the basics loaded. Everything else lives in modules, and import loads one so you can use what's inside it.

WriteThen use it asMeans
import csvcsv.DictReader(…)load the whole module; reach in with a dot
from datetime import datedate.today()load just one thing, and use it by its own name

Imports go at the top of the file. Some modules come with Python, the standard library, so there's nothing to install. The ones support scripts use most:

ModuleFor
csvreading and writing spreadsheet-style files
jsonturning JSON text into dicts and lists, and back
datetimedates and times, and the gap between them

collectionsCounter, a shortcut for counting by group

Libraries that don't come with Python, like requests for calling APIs, are installed with pip, into the active environment (the .venv you activated in Lesson 7):

pip install requests              # one library
pip install -r requirements.txt   # everything a project lists
pip list                          # what's installed here

A project's requirements.txt lists the libraries it needs, so anyone can set it up with one command. The course has one: open it and you'll see requests and pytest. If you see ModuleNotFoundError: No module named '…', it almost always means "not installed in this environment" or "environment not active".

2. Where Python looks for a file

When you write open("data/harbor_invoices.csv"), that's a relative path: Python starts looking in the folder you were in when you ran the script, not the folder the script lives in. That folder is called the working directory. pwd in the terminal shows it.

You're inYou run"data/harbor_invoices.csv" means
support-skills/workspacepython lesson10/invoice_summary.py …workspace/data/harbor_invoices.csv: found
support-skillspython workspace/lesson10/invoice_summary.py …support-skills/data/harbor_invoices.csv: FileNotFoundError

Same script, same file, different folder, different result. So when a file "obviously exists" and Python can't find it, check where you ran from. In this course: always from workspace. The boxes on these pages run from there too.

An absolute path starts from the top of the disk, like /Users/you/Developer/support-skills/workspace/data/harbor_invoices.csv. It works from anywhere, but only on your machine, so scripts take paths as relative or from the command line instead (section 7).

3. Opening and reading a file

Every file read in Python looks like this:

with open("data/harbor_invoices.csv") as f:
│    │                                 └ as f: call the open file f (any name works)
│    └ open(path): open the file for reading and give back a file object
└ with: keep it open for the indented block, then close it, even if something crashes

    lines = f.readlines()     # inside the block: read from f

The file object f is a handle on the file, not its contents. You read from it with one of these:

WriteGives youGood for
f.read()the whole file as one stringsmall files you'll search as text
f.readlines()a list of strings, one per linecounting lines, picking out line 1
for line in f:one line at a timebig files: logs, long exports
f.readline()just the next linereading a header, or one sample

Each line keeps its line break at the end, written \n. That's why .strip() appears so often when reading files:

Once the with block ends, the file is closed, but lines is an ordinary list and you can keep using it. Read inside the block; work with the result after.

4. CSV files

A CSV is a text file where each line is a row and commas separate the columns. The first line is usually the header, naming the columns. The start of Maya's export:

Number,Client,Status,Amount,Currency,Issued,Due,Paid on
INV-0001,Westfield Motors,paid,713.50,USD,2025-11-04,2025-12-04,2025-12-04
INV-0002,Greenway Farms,paid,3968.00,USD,2025-11-13,2025-12-28,2025-12-30

You could .split(",") each line yourself, but a client called "Smith, Jones & Co" has a comma in its name, and CSVs put quotes around values like that. Splitting on commas would cut the name in two. The csv module handles the quoting for you, and csv.DictReader goes one better: it gives you each row as a dict.

Line by line:

  1. import csv loads the CSV toolkit.
  2. with open(…) as f: opens the file as f, and closes it when the block ends.
  3. csv.DictReader(f) reads the first line as the column names, then turns every line after it into a dict with those names as keys:
    {"Number": "INV-0044", "Client": "Lakeshore Group", "Status": "overdue", "Amount": "4171.00", …}
    The for loop hands you one of those dicts at a time as row. The header line never comes through as a row of its own.
  4. if row["Status"] == "overdue": looks up the Status for this row and keeps going only when it's exactly "overdue". This is where status = 'overdue', one row at a time.
  5. print(…) shows three of the row's values, with spaces between them.

Read as a whole: open the invoices; for each row, as a dict keyed by the header; if it's overdue, print its number, client and amount. It's select number, client, amount from invoices where status = 'overdue', written as a loop.

Everything from a CSV is text

A CSV has no types. row["Amount"] is "4171.00", a string, so adding amounts glues text together or crashes. Convert first, with Lesson 7's tools:

Column holdsConvert with
money, decimalsfloat(row["Amount"])
whole numbers, idsint(row["Seats"])
textnothing, but often .strip(), and .lower() before comparing
an empty cellit's "", not None; float("") is a ValueError

And the keys match the header exactly: capitals and spaces count. row["status"] is a KeyError when the header says Status, and the last column here is row["Paid on"], with the space.

5. JSON

JSON is the format APIs send and logs are often written in. You met it in Lesson 5. To Python, JSON arriving from a file or an API is just text, until you turn it into dicts and lists with json.loads ("load string"). json.dumps goes the other way.

6. Writing a file

Writing looks like reading with one extra argument. "w" means write: it creates the file, or replaces it if it already exists.

with open("overdue.txt", "w") as f:
    f.write("INV-0044 Lakeshore Group\n")   # write doesn't add a line break; \n does
    f.write("INV-0040 Westfield Motors\n")

Use "a" instead of "w" to add to the end of a file without wiping it. Lesson 12 writes a CSV with csv.writer, which is the same idea with commas handled for you.

7. The shape of a real script

Almost every script you'll write or read at work is laid out the same way:

"""What this script is for, and how to run it."""   # 1. a docstring at the top
import csv                                          # 2. imports
import sys

def read_invoices(path):                            # 3. small functions, one job each
    ...

def main():                                         # 4. main() runs the steps in order
    path = sys.argv[1]
    ...
    return 0

if __name__ == "__main__":                          # 5. run main() when run as a script
    sys.exit(main())

The new pieces, one at a time:

  • The docstring is a string in triple quotes at the very top. It does nothing when the script runs; it's there for the next person to read, and they often say how to run the script.
  • sys.argv is a list of the words typed on the command line. For python lesson10/invoice_summary.py data/harbor_invoices.csv, it's ["lesson10/invoice_summary.py", "data/harbor_invoices.csv"]. Item 0 is always the script itself, so the first thing you typed after it is sys.argv[1]. That's how one script works on any file you give it. (Lesson 14 upgrades this to proper options like --dry-run.)
  • main() is an ordinary function. By convention it's the one that does the steps in order and the only one that prints the results; the other functions work things out and return.
  • if __name__ == "__main__": means "only when this file is run directly". When a test file imports your script to check its functions, main() doesn't run. Copy the line as it is; nearly every Python script ends with it.
  • sys.exit(main()) passes main's return value back as the exit code: 0 for success, anything else for failure. Schedulers and other scripts use it to tell whether a run worked.

9. Notebooks

A script is for a job you'll run again. A notebook is for poking at data to find out what's going on: code in cells, run one at a time, with each result shown right under its cell. CX operations teams live in them; so do analysts. The common ones are Jupyter (which Cursor and VS Code open directly), Google Colab (Jupyter in a browser, free with a Google account), and hosted tools like Hex.

Open workspace/lesson10/explore.ipynb in Cursor:

  1. If Cursor offers to install the Jupyter extension, accept.
  2. Click Select Kernel (top right) → Python Environments → the one in support-skills/.venv. The kernel is the Python that runs the cells; it needs to be the course's environment so the libraries are there.
  3. Click into the first cell and press Shift Enter to run it and move on. Run each cell in order.

Notice two differences from a script. The last line of a cell is displayed without print. And variables stay alive between cells, so you can try something, look, and change one cell without starting over. That's what makes notebooks good for exploring, and also what makes them messy: run cells out of order and the results stop matching the code. When an exploration becomes a job you'll repeat, turn it into a script.

Recap

  • import the standard library; pip install everything else into the active environment.
  • Relative paths start from the folder you ran from. In this course, that's workspace.
  • with open(path) as f: reads; open(path, "w") writes (and replaces). Lines end in \n; .strip() it.
  • csv.DictReader gives each row as a dict keyed by the header. Every value is text: convert before math.
  • json.loads turns JSON text into dicts and lists; null becomes None.
  • A script: docstring, imports, small functions, main(), if __name__ == "__main__":. sys.argv[1] is the first thing typed after the script.
  • Notebooks for exploring, scripts for jobs you'll run again.
